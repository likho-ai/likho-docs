- Every interface is defined once in `likho-contracts`; references, the Postman collection and client code are generated from that definition.
- | Interface | Users | Source of truth | Reference people open | Checked by |
  | --- | --- | --- | --- | --- |
  | REST `/api/v1` | scripts and other internal apps | `openapi/likho.v1.yaml`, generated by `@nestjs/swagger` from likho-api's controllers and DTOs, and committed | `/api/docs` (Scalar) and the Postman collection | Newman in CI; schema diff must be non-breaking |
  | GraphQL `/graphql` | the web apps | `schema.graphql`, generated by NestJS (code-first) and committed | GraphiQL in development; schema reference page in likho-docs | schema diff in CI must be non-breaking; generated hooks must type-check in every web app |
  | gRPC | service to service | `proto/likho/*/v1/*.proto` | pages generated by `protoc-gen-doc` into likho-docs; Postman gRPC requests from the same protos | `buf lint`, `buf breaking`, contract tests |
  | Events | service to service | `events/*.schema.json` + `asyncapi.yaml` | AsyncAPI HTML in likho-docs | example events validated in CI |
- ## Postman
	- ```
	  likho-contracts/postman/
	  ├── Likho Public API.postman_collection.json     # generated: openapi-to-postmanv2
	  ├── Likho Internal gRPC.postman_collection.json
	  ├── environments/  local.json  staging.json  production.json   # base_url, api_key (empty)
	  └── README.md
	  ```
	- Workspace **Likho**; CI pushes the generated collections with the Postman API on every tagged release of likho-contracts. No secret is stored in a collection or environment file; `api_key` is filled in locally. * Folder **Getting started**: create an API key → `POST /recordings` → `GET /jobs/{id}` → `GET /transcripts/{id}` → `GET /search`. Each request has a saved example response and a test script asserting status and shape; Newman runs the folder against the Compose stack in likho-api's CI.
- ## Public REST API v1
	- | Method and path | Purpose |
	  | --- | --- |
	  | `POST /api/v1/recordings` | Upload a file (multipart) or register a dialer call `{ crtObjectId }` to fetch |
	  | `GET /api/v1/recordings` / `{id}` | List with filters (status, campaign, agent, date) / details |
	  | `POST /api/v1/recordings/{id}/transcribe` | Queue a job `{ model?, language? }` |
	  | `GET /api/v1/jobs/{id}` | Progress; `GET /api/v1/jobs/{id}/events` streams lines (SSE) |
	  | `GET /api/v1/transcripts/{id}?format=json\|txt\|srt\|vtt` | Both layers, or an export |
	  | `GET /api/v1/calls/{crtObjectId}/transcript?leg=` | Transcript by dialer id, for other internal apps |
	  | `PATCH /api/v1/transcripts/{id}/segments/{idx}` | Correct a line |
	  | `GET /api/v1/search?q=&language=&from=&to=` | Search |
	  | `GET/POST/DELETE /api/v1/vocabulary/glossary`, `/spellings` | Vocabulary |
	  | `POST /v1/audio/transcriptions` | OpenAI-compatible endpoint for existing tools |
	- Auth: `Authorization: Bearer lk_…` (API key) → internal JWT. Errors use one shape: `{ "error": { "code": "recording_not_found", "message": "…", "requestId": "…" } }`. Lists are cursor-paginated (`?cursor=&limit=`). Times are ISO 8601 with offset; dialer times are also returned as given (IST text).
- ## Documentation site
	- `likho-docs` is a Logseq graph published to GitHub Pages (the docs.torahanytime.com setup). CI in likho-contracts regenerates and commits the API pages there: REST reference link, gRPC pages, AsyncAPI event catalogue. Each service keeps a README (run, env, ports) and one page in the site (purpose, data, interfaces, runbook).
